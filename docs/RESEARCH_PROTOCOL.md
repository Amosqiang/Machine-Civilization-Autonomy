# MCAB Research Protocol

字段语义、场景记录方式、评分边界及校验命令见 [MCAB v0.1工作规范](MCAB-v0.1.md)。该规范仍为草案，补充本协议的操作细节，不代表已完成基线研究或本体冻结。

跨行业前沿证据如何选题、检索、核验与反馈，见方法回环 [METHOD_LOOP.md](METHOD_LOOP.md)（`build_target_queue.py` / `source_playbooks.csv` / `cycle_log.csv`）。

## 研究对象
MCAB 研究的不是单个模型，而是“AI + 机器人 + 能源 + 原材料 + 制造 + 半导体 + 物流 + 经济调度”构成的机器文明系统。

## 核心反事实
给定某一技术年份 t，逐步移除人类参与，测量系统是否仍能：
1. 运行；
2. 发现异常；
3. 诊断故障；
4. 修复；
5. 获取关键输入；
6. 保持能源供应；
7. 保持知识与软件连续性；
8. 灾后恢复；
9. 扩容；
10. 复制出下一套同等能力系统。

## Human Removal Test
对每个子系统至少评估以下场景：
- HR100：100% 人类参与，现实基线；
- HR50：人类劳动/决策减少50%；
- HR10：只保留10%关键人类岗位；
- HR1：只保留极少数“最后脐带”岗位；
- HR0：完全无人类参与。

重点不是线性插值，而是识别性能曲线中的断崖与临界点。

## 统一自主等级
- 0 / H5：完全寄宿，关键操作必须依赖人类；
- 1 / H4：自动运行，但异常处理和维护依赖人类；
- 2 / H3：局部自治，可处理常见故障；
- 3 / H2：高度自治，多数维护、输入与扩容可自主完成；
- 4 / H1：近乎独立，仅少量关键输入依赖人类；
- 5 / H0：宿主独立，可长期无人运行、恢复、扩容和复制。

## 证据等级
每条评分必须附证据，并区分：
- E5：现实长期无人生产运行数据；
- E4：现实短期无人实验 / 工业现场验证；
- E3：高保真试验场 / 原型系统；
- E2：实验室演示；
- E1：仿真、模型或厂商声明；
- E0：无直接证据，仅推断。

评分不得仅依据模型能力宣传、demo视频或单一厂商声明。

## 置信度
- High：多来源、一致、现实运行证据；
- Medium：单一高质量来源或局部现实证据；
- Low：实验室、仿真、推断或信息缺失。

## 关键路径原则
MCAB 不以简单平均分代表文明独立性。若一个关键节点不可替代，则其低分可成为全系统上限。

关键路径分析至少记录：
- dependency：依赖哪些上游系统；
- substitutes：是否存在替代路径；
- recovery_time：失效后的恢复时间；
- stockpile_duration：库存可维持时间；
- single_point_of_failure：是否为单点故障；
- human_last_mile：最后不可替代的人类岗位/技能。

## 四个总指标
### C — Closure
工业闭环度，强调关键路径而非质量占比。

### H — Human Dependence
移除人类后系统性能的损失程度。

### R_M — Machine Reproduction Number
一套完整机器工业系统在生命周期中平均能建立多少套同等能力后代系统。

### g_0 — Human-free Growth Rate
HR0 条件下机器资本/有效生产能力的长期净增长率。

## 年度基线
每年发布一次：MCAB-2026、MCAB-2027……

年度更新包括：
1. 1000维评分；
2. 证据变化；
3. 前10个关键瓶颈；
4. “最后的人类脐带”清单；
5. C/H/R_M/g_0 的区间估计；
6. 与上一年对比；
7. 3年、5年、10年情景推演。

## 研究边界
MCAB 是技术—工业自主性研究，不等同于：
- AI安全总体评估；
- 道德价值判断；
- 对AI主观意识的判断；
- 对未来冲突的必然性预测。

它只回答：机器系统在减少人类参与后，物理与经济上的连续性、自主性、复制性和增长性达到什么程度。
